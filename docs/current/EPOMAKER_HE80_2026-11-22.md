# EPOMAKER HE80 (0C45:8092) on the Sonix / MINI60 backend

Tester capture, 2026-11-22 (Windows 11, USB, probe 0.2.1, USB release 1.17).

## Identity
- USB `0C45:8092`, product string "Epomaker HE80". Collections: FF68:0061 (65-byte in/out, command and
  stream channel) and FF67:0061 (4097-byte output, bulk; never touched). Same layout as the AJAZZ AK820 / AK680 V2.
- Passive listening is silent: analog data only arrives after command 0x66 (stream on). 0x67 stops it.
- Device info (0x10): the AA/55 frame format of the MINI60 backend is accepted.

## Stream behaviour (differs from the AK820)
- Packets `55 FB key status high low adc travel stroke` decode with the existing `Decode`.
- Held keys are repeated continuously, including unchanged values (travel 260 / adc 1988 repeated for many
  reports while another key moved). So the MINI60 per-key 50 ms freshness path (`Read`) is used, not the AK820
  change-only hold path (`Held`).
- Two keys moving together alternate packet by packet and both report press and release. Idle keys can also
  appear with drifting travel 0..14 (0.01 mm). Three or more simultaneous keys: see Open items.
- Travel reaches 400 (4.00 mm) at the bottom; the packet stroke byte was 38 on the keys sampled.

## Key map
78 positions captured by pairing the stream key id with the OS key event (SDL scancode = HID usage).
77 are identical to the AK820 Driveall table; Insert (103, usage 73) is the only addition.
Esc (0), Left Alt (82), Space (83), End (107) and Fn (85) were not captured yet and are taken from the AK820
table. `He80Factory` therefore has 83 positions.

## Implementation
`He80Pid`, `He80Factory`, `Driveall()`, identity by VID/PID echo (as AK820), discovery filter, device name.
Layout token reuses the AK820 MAX HE ANSI preset (same positions; Insert is not drawn).
